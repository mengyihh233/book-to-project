# 学习区交互简化计划

状态：设计草案。公开仓库与本地学习区版本不同，本文不代表以下功能已在主分支实现。

## 用户希望怎样学习

首页先看到自己的项目工作区，下面再看教材和教学项目。自由探索时，资料提供对照，助手在用户提问时帮助定位；代码尝试和问题经用户确认，逐步积累为作品与知识网络。

## 页面分工

- 自由练习：只列项目文件夹和工作区，不扫描、预览或编辑源码。
- 教材与例子：阅读知识和参考代码；试改某个例子时打开这个例子自己的编辑器副本。
- VS Code：编写、运行与调试。电脑本地版和平板网页版都保留 Windows / Ubuntu 选择，实际目录和运行环境一致。
- 资料与助手：在编辑器侧栏按当前文件列相关资料，由用户点开；助手不自动对话、催进度或安排任务。

## 简化规则

1. 合并用途相同的“自由练习/项目区”入口；单题和整科操作放在对应上下文，不堆在首页一排。
2. 例子与习题用途清楚。“试改本例”不应转去另一道综合题，也不以网页输出代替写代码实践。
3. 题面保留完整要求、输入输出、边界和参考答案。去掉固定七段/三段导学模板，避免每题重复运行流程。
4. 测试覆盖、版本进度、完成口径和维护说明进入维护文档；来源用简短标签或按需查看。
5. 保留章节与题目并列、全部任务、独立教材入口及阅读返回位置。减少同时显示的控件，不另造一套大导航。

## 实施优先级

1. 项目登记可靠性：稳定ID、并发写入保护、原子保存、备份与损坏文件保护。
2. 统一打开目标：项目根、系统、文件及行列共用一份解析，校验登记根，不靠放开任意路径。
3. 当前文件上下文：桌面扩展、网页宿主、助手接收方共用协议；定位失败明确显示，不猜路径。
4. 运行与断点：在编辑器内提供一致动作，避免为每例复制一套长教程。
5. 按需收录：用户直接收录，或请助手整理后确认。链接原文件，不复制代码，不把打开页面视为学习完成。

## 完成检查

- 自由项目入口只请求项目元信息，不请求源码，不自动运行程序。
- 编辑例子会到该例自己的副本；已修改副本不被覆盖。
- Windows盘文件通过WSL访问时仍是同一份；Ubuntu home项目使用正确的Linux路径。
- 不可达、未启动和不存在分别反馈；不自动重装、重启或停止服务。
- 资料条目能跳到真实教材/例子，切换资料保留代码现场与阅读位置。
- 教学文字没有固定开场模板，题干和答案仍完整可查。
- 本机、私有HTTPS、真实平板、原生编辑器和参数夹具的结果分别记录。一次成功不代表间歇故障已经根治。

## 版本与数据

本地新实现需逐项检查公开仓库的接口后再移植。提交只包含本项目的公共实现与说明，不包含私人教材、个人作答、笔记、进度、认证或模型密钥。学生文件与历史学习记录不因界面整理而重写。
