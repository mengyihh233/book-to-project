# 第17章 创建函数

> **要干什么：** 创建函数：参数传递、返回值与局部变量。

## 1 · 题目是什么

创建函数：参数传递、返回值与局部变量

原书页码：PDF 第 371 页。

## 2 · 实现什么

把这一章要用的命令和判断逻辑写成一个能重复运行的脚本，不是敲一遍就算。

## 3 · 写在哪里

**work.sh**。

## 4 · 怎么做

先弄清这几点：

- 完成后请回答：这一步为什么这样写？换一种写法会在什么情况下出错？
- 把命令行随手敲出来的命令，整理成可重复运行的脚本，是这一章的核心。

动手顺序：

1. 先读原书对应小节。
2. 打开 `work.sh`，在 TODO 处写自己的实现。
3. Ctrl+Shift+B 选「本题：运行作答」，看末尾的验收结果。
4. 全过 → 去下一章；有 FAIL → 对照 `reference.sh` 找出差异，不要直接抄。

## 5 · 文本格式

脚本按题目要求往标准输出写结果；以脚本末尾 check 的结果为准，不要打印多余提示语。

## 6 · 哪个是判分的

**只有一个：脚本末尾的 check，以及 VS Code 任务“本题：检查作答”。** 全部 PASS 才算完成；编译成功不等于做对。

`work.sh` 末尾的 check 全部 PASS（共 3 项）即为完成。
自己写的实现只要输出一致就算过，不要求和参考实现逐字相同。

参考实现见 `reference.sh`；静态检查用「Shell：检查语法」。

1. 打开本题自己的作答文件，保存修改。
2. **运行：** Ctrl+Shift+B，或“任务：运行任务” → **本题：运行作答**。这一步不判题。
3. **核对：** “任务：运行任务” → **本题：检查作答**。本题没有独立自动评分。检查入口会明确提示人工自检，不把参考实现通过或编译成功当作你的作答通过。

input.txt是手动测试输入；检查数据不是填答案的位置。无需自己挑选判分脚本，“本题：检查作答”会读取本题规则。

## 7 · 做完的标准

脚本末尾的 check 全部 PASS，并且你能说清这条命令为什么这样写、换一种写法会在什么情况下出错。
