# 有理数类：提示与核对

先写过预测和自己的实现，再看[完整参考](参考实现/rational.cpp)。这是自编适配答案。

## 从用户需要倒推表示

1/3、2/6和-1/-3表示同一个数。构造时统一成唯一表示，==只需比较两个成员；每个操作都复用同一个 normalized，避免四个运算各写一套约分。分母正、互质、0/1是成功对象的不变量。

零分母先拒绝；把负号移到分子；用gcd约分。gcd(0,d)=d，所以零会自然约为0/1。只有规范化完成后才检查32位存储范围，避免本可约掉的大中间数被过早拒绝。

## 四则运算与const

手算a/b+c/d=(ad+cb)/bd，其余从分数运算推导。成员函数const说明左操作数不变；返回值是新对象。1/2+1/3=5/6，继续加1/6=1/1；显示1/1与整数1代表同一个有理数。

先把参与运算的成员转为int64，再做乘法；`int64_t x = int32_a * int32_b`会先在较窄类型里乘，赋值时已经太晚。分母存储上界为2^31-1，分子范围[-2^31,2^31-1]。单个乘积至多约2^62；加减的最坏交叉乘积结果仍严格落在int64范围内。本项目只有这些受限入口，没有向外公开任意int64输入的normalized。

特别注意最小负整数：不要在int32中对INT32_MIN取负或abs。本参考先提升成int64再处理符号。最终值超出存储范围明确抛out_of_range。它只对本项目int32接口保证中间计算范围，不可直接改为任意int64成员后仍照搬公式。

## 你应该能解释的现象

- `2/-4 -> -1/2`，`0/-7 -> 0/1`。
- `1/0`和除以0/1都失败，但对象原值不变。
- `INT32_MIN/INT32_MIN -> 1/1`，不能因为中间要换符号就提前溢出。
- `1/MAX+(MAX-1)/MAX -> 1/1`：先约分再检查结果范围。
- `MAX/1+1/1`超范围，`1/MAX*1/MAX`的分母也超范围，不返回不正确的结果。

## CMake如何连接这些文件

include/rational.hpp描述接口；我的作答/rational.cpp或参考实现/rational.cpp提供唯一一份实现，编成静态库rational；demo.cpp和tests.cpp分别提供自己的main，生成两个独立可执行文件。PUBLIC的包含目录和C++17要求会传给使用库的目标。PRIVATE链接把当前可执行目标依赖的库写清楚。

include(CTest)允许注册测试；CTest只有一个rational_contract项目，其中执行22项契约核对。不是22个独立CTest条目。测试不用assert，Release构建也不会因NDEBUG跳过检查。参考通过不会自动记录个人完成。
