# 第 2 章例题讲解：函数与库

本讲解配合 Eric Roberts《C++程序设计：基础、编程抽象与算法策略》第 2 章阅读。下面的页码均为 **PDF 查看器页码**；例如 PDF 第 56 页对应书内第 41 页。示例中的补充代码为教学改写，不是原书习题答案。

阅读时先回答三个问题：这个函数需要什么输入？它返回什么结果？调用之后，调用者的变量是否会改变？随后再看语法。

## 1. 声明、定义、调用：先把三件事分开

函数可以理解为有名字的一段操作。声明告诉编译器“这个名字如何使用”，定义写出实际操作，调用要求程序现在执行它。

```cpp
#include <iostream>

bool isEven(int n);                  // 声明：需要 int，返回 bool

int main() {
    int count = 6;
    bool answer = isEven(count);     // 调用：把 count 的值传进去
    std::cout << std::boolalpha << answer << '\n';
}

bool isEven(int n) {                 // 定义：函数头加函数体
    return n % 2 == 0;
}
```

运行结果为 `true`。原书在 [PDF 第 56 页](../../../../books/cpp-roberts.pdf#page=56) 用 `isEven` 说明返回布尔值的判定函数。上面的完整程序补出了声明和调用，方便观察三者的关系。

| 代码部分 | 怎么读 |
| --- | --- |
| `bool` | 调用结果的类型是布尔类型。 |
| `isEven` | 函数名。 |
| `int n` | 形参：函数内部用来接收输入的名字。 |
| `count` | 实参：这次调用实际传入的表达式。 |
| `return n % 2 == 0;` | 求出一个布尔值，并把它交还调用者。 |

这次调用时，`n` 获得数值 `6`。它和 `main` 中的 `count` 是不同的变量，名字也不必相同。`answer` 接收返回值，而不是接收函数的整个执行过程。

原型末尾有分号，函数定义的大括号后通常不加分号。若把完整定义放在 `main` 前面，定义本身也提供了声明信息；若定义放在调用之后，就先写原型。本章先沿用原书的“原型在前、`main` 在中、函数定义在后”形式。

### 返回值与 `void`

需要计算一个结果时，选择明确的返回类型，例如 `int`、`double`、`bool`。只执行动作时，可以使用 `void`：

```cpp
void printSeparator() {
    std::cout << "--------\n";
}
```

`printSeparator();` 是合法调用；`int x = printSeparator();` 不合法，因为它没有可赋给 `x` 的返回值。`void` 函数可以用 `return;` 提前结束；返回非 `void` 的普通函数应在正常执行路径上返回相应类型的值。

## 2. 重载：名字相同，参数列表不同

原书 [PDF 第 57 页](../../../../books/cpp-roberts.pdf#page=57) 使用不同参数类型的绝对值函数说明重载。下面换成更容易逐项比较的“取较大值”：

```cpp
int larger(int a, int b) {
    return a > b ? a : b;
}

double larger(double a, double b) {
    return a > b ? a : b;
}
```

| 调用 | 入门阶段的判断方法 |
| --- | --- |
| `larger(3, 5)` | 两个实参都是 `int`，匹配 `int` 版本，得到 `5`。 |
| `larger(3.0, 5.5)` | 两个实参都是 `double`，匹配 `double` 版本，得到 `5.5`。 |
| `larger(3, 5.5)` | 对这两个重载而言，没有唯一更优匹配，编译器会报告歧义。明确统一类型后再调用。 |

先不要把重载理解为“编译器看返回值决定用哪一个”。下面两个声明仅返回类型不同，不能构成合法重载：

```cpp
int readValue(int index);
double readValue(int index);  // 错误示例：参数列表没有区分
```

同样，把形参名从 `n` 改成 `count` 也不会产生新重载。初学时重点检查参数的数量、类型和顺序。

## 3. 默认参数：省略的是调用处的尾部实参

原书 [PDF 第 57–58 页](../../../../books/cpp-roberts.pdf#page=57) 用默认列数和初始坐标说明默认参数。下面用测量换算练习同一机制：

```cpp
double pixelsToMm(double pixels, double mmPerPixel = 0.25);

double pixelsToMm(double pixels, double mmPerPixel) {
    return pixels * mmPerPixel;
}
```

```cpp
double a = pixelsToMm(40);        // 相当于 pixelsToMm(40, 0.25)，得到 10
double b = pixelsToMm(40, 0.10);  // 显式传入尺度，得到 4
```

这里的 `0.25` 表示每个像素对应 `0.25 mm`，只是练习数据。实际机器视觉项目的尺度需要来自相应的测量或标定。

按本章采用的“单独原型加定义”写法，记住三点：

1. 默认值写在调用处可见的声明中，定义里不要再重复写同一个默认值。
2. 可省略的实参位于尾部。例如 `void f(int a, int b = 2);` 可以写 `f(1)`，不能通过空位跳过第一个实参。
3. 默认值表示调用者可以省略输入，不代表函数会自动检查输入是否合法。

更精确地说，函数定义本身也是一种声明，因此不能把这种书写约定记成“任何函数定义都绝不能写默认值”。本讲解把默认值统一放在独立声明处，便于初学者保持一致；同一参数的默认值不能在后续声明中重复指定。[C++ 工作草案：默认实参](https://eel.is/c++draft/dcl.fct.default)

也可以用重载明确区分不同用法。例如只接受 `setInitialLocation()` 或 `setInitialLocation(x, y)`，就写无参数版本和双参数版本；两个参数都设默认值，还会允许只传入一个参数。原书在 [PDF 第 58 页](../../../../books/cpp-roberts.pdf#page=58) 提醒读者考虑这种接口差别。

## 4. 组合数：把大问题分成三个职责

原书 [PDF 第 59 页](../../../../books/cpp-roberts.pdf#page=59) 用“从 6 枚不同硬币中选 2 枚”引出组合数。关键是只看选中了哪两枚，不区分拿取先后顺序。

公式为：`C(n, k) = n! / (k! × (n-k)!)`，其中 `0! = 1`，合法输入满足 `n >= 0` 且 `0 <= k <= n`。

原书 [PDF 第 60 页图 2-2](../../../../books/cpp-roberts.pdf#page=60) 将程序分为三个函数：

| 函数 | 职责 | 示例输入、结果 |
| --- | --- | --- |
| `main` | 获取输入、调用计算、显示结果。 | 输入 `6 2`，显示 `15`。 |
| `combinations` | 根据组合数公式组织计算。 | `combinations(6, 2)` 得到 `15`。 |
| `fact` | 只计算一个非负整数的阶乘。 | `fact(6)` 得到 `720`。 |

先读 `fact`：

```cpp
// 本小例要求 n >= 0，且所有乘法结果都在 int 可表示范围内。
int fact(int n) {
    int result = 1;
    for (int i = 1; i <= n; ++i) {
        result *= i;
    }
    return result;
}
```

用 `fact(4)` 手算：

| 时刻 | `i` | `result` |
| --- | --- | --- |
| 初始化 | 尚未进入循环 | `1` |
| 第 1 次乘法后 | `1` | `1` |
| 第 2 次乘法后 | `2` | `2` |
| 第 3 次乘法后 | `3` | `6` |
| 第 4 次乘法后 | `4` | `24` |
| 下一次条件检查 | `5`，不满足 `i <= 4` | 返回 `24` |

`fact(0)` 不进入循环，返回初值 `1`，符合 `0! = 1`。但是 `fact(-1)` 也会不进入循环，所以不能把它返回 `1` 当成负数阶乘合法的证据；调用前应检查输入。

### 追踪时先拆表达式，明确执行顺序

原例的核心表达式为：

```cpp
return fact(n) / (fact(k) * fact(n - k));
```

**不能因为它写在一行里，就认定三个 `fact` 调用一定从左到右执行。** 括号规定乘除如何分组，不保证这里各个函数调用的先后次序。若给 `fact` 加打印，观察到的某次顺序只是该次运行现象，不能当作语言保证。[C++ 工作草案：执行顺序](https://eel.is/c++draft/intro.execution)

这三个调用只依赖各自输入时，调用次序不会改变这个小范围例题的数学结果。为了用日志或纸笔逐步跟踪，把它改写成明确的多条语句：

```cpp
int combinations(int n, int k) {
    int numerator = fact(n);
    int leftDenominator = fact(k);
    int rightDenominator = fact(n - k);
    int denominator = leftDenominator * rightDenominator;
    return numerator / denominator;
}
```

以下表格的顺序由**这份拆分代码**保证：

| 步骤 | 调用者正在等待什么 | 本步结果 |
| --- | --- | --- |
| 1 | `main` 等待 `combinations(6, 2)` | 进入 `combinations`，本次形参为 `n=6, k=2`。 |
| 2 | `combinations` 等待 `fact(6)` | 该次 `fact` 返回 `720`，存入 `numerator`。 |
| 3 | `combinations` 等待 `fact(2)` | 返回 `2`，存入 `leftDenominator`。 |
| 4 | `combinations` 等待 `fact(4)` | 返回 `24`，存入 `rightDenominator`。 |
| 5 | 已得到三个阶乘 | `denominator = 2 * 24 = 48`。 |
| 6 | `main` 仍在等待组合数 | 返回 `720 / 48 = 15`，随后由 `main` 显示。 |

每次调用都有自己的形参和局部变量。`fact(6)` 的 `n` 与 `combinations(6, 2)` 的 `n` 同名，但不是同一个变量；另一次 `fact(2)` 也会有自己的 `n`、`i`、`result`。原书用栈帧图展示这一点，入门时可把每次调用画成一张独立的小卡片。

不要把分母括号去掉。`fact(n) / fact(k) * fact(n-k)` 会按乘除的结合规则形成另一种计算，例如 `720 / 2 * 24 = 8640`，已经不是组合数公式。

### `int` 范围是例题成立的条件

`int` 的范围由实现决定，可用下面的语句查看当前环境的上限：

```cpp
#include <limits>
// 在 main 中执行：
std::cout << std::numeric_limits<int>::max() << '\n';
```

在上限为 `2147483647` 的常见 32 位 `int` 环境中，`12! = 479001600` 可以表示，`13! = 6227020800` 已经超出范围。有符号整数溢出属于未定义行为，不能依靠“变成负数”或“绕回来”检测它。[C++ 工作草案：表达式的可表示范围](https://eel.is/c++draft/expr.pre)

最终答案小，也不能保证中间量安全。例如 `C(20, 1) = 20`，但先求 `20!` 的实现会在常见 32 位 `int` 上先溢出。把变量换成 `long long` 只是扩大有限范围；仍须验证输入和中间结果。

本章先把组合数当作**小范围调用追踪练习**：确认当前整数范围，限制输入，再运行。后续可以学习逐次约分或其他组合数算法。带乘法前检查的阶乘练习见[实操路线](实操路线.md)。

## 5. 从按值传参走向引用参数

已核对的 [PDF 第 64 页](../../../../books/cpp-roberts.pdf#page=64) 下半页开始 2.5，先说明：传递普通变量的值时，被调函数获得副本，修改普通形参不会改变调用者的变量。本页后续内容在下一页继续，因此下面的交换程序标为**自编对照例**，不作为该页原例的转录。

```cpp
void changeCopy(int value) {
    value = 99;
}

void changeOriginal(int& value) {
    value = 99;
}
```

```cpp
int count = 3;
changeCopy(count);       // count 仍为 3
changeOriginal(count);   // count 变成 99
```

`int& value` 表示引用形参。调用时，`value` 绑定到调用者传入的那个整数对象；通过它赋值会修改原变量。这里的 `&` 出现在形参声明中，先把它读成“这个参数引用原对象”。

交换两个变量因此可以写成：

```cpp
void swapValues(int& a, int& b) {
    int temporary = a;
    a = b;
    b = temporary;
}
```

若初值为 `x=-3, y=8`，执行 `swapValues(x, y)` 后是 `x=8, y=-3`。临时变量保留了旧的 `a`，否则先写 `a=b` 就会丢掉原值。再用相等值和 `swapValues(x, x)` 检查同一个变量被传入两次的情况。

选择接口时先看目的：只需读一个小整数时，按值传参直观；需要修改调用者对象时，再明确使用引用。函数名、注释和测试应让调用者知道哪些参数会被改变。
