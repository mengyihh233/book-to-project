# 第 2 章实操路线：把函数跑明白

下面 6 个练习是围绕 Roberts 第 2 章编写的配套实操，编号为 `CH02-P01` 至 `CH02-P06`，**不是原书同号习题**。原书阅读入口见[例题讲解](例题讲解.md)，主要对应 [PDF 第 56–60 页](../../../../导入教材.md#这两份文件为什么不在仓库里)，以及 [PDF 第 64 页开始的引用参数内容](../../../../导入教材.md#这两份文件为什么不在仓库里)。

每题都按四步做：先在纸上预测，再编译运行，每次只改一个因素，最后检查结果并用中文解释原因。不用为6项各建文件：可在同一份练习源码里逐项观察，始终保留一个main；也可先只选自己薄弱的1项。已有作答另存并保留，不能覆盖自己的记录。文中的机器视觉场景只使用几个普通数值，不需要相机、OpenCV 或额外库。另有[函数实验示例](讲解示例/函数实验/README.md)可作集中对照，建议先完成自己的预测再查看。

## 开始前：建立一个重复可用的运行流程

在已经配置好 C++ 编译器的 Linux 终端中，可以用如下命令编译和运行。若当前环境没有 `g++`，先沿用项目已有的编译运行入口；本路线不要求安装软件。

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic p01.cpp -o p01 && ./p01
```

`p01.cpp` 是源文件，`p01` 是本次生成的可执行文件；`./p01` 表示运行当前目录中的这个文件。`&&` 保证只有编译成功后才运行，能避免误把上一次的旧程序输出当作新结果。后面各题相应换成 `p02`、`p03` 等文件名。

每题建议记录四行：`我的预测`、`实际结果`、`本次改动`、`原因说明`。编译错误也是可观察结果；先读报错位置，确认修复并重新编译成功后再运行。

## CH02-P01：用判定函数检查有界计数

场景：一个小程序收到“这一批检测到的目标数”。我们先约定合法范围为 `0..limit`，包括两个端点。

把下列代码保存为自己的 `p01.cpp`：

```cpp
#include <iostream>

bool isCountValid(int count, int limit);

int main() {
    std::cout << std::boolalpha;
    std::cout << isCountValid(0, 5) << '\n';
    std::cout << isCountValid(5, 5) << '\n';
    std::cout << isCountValid(-1, 5) << '\n';
    std::cout << isCountValid(6, 5) << '\n';
}

bool isCountValid(int count, int limit) {
    return count >= 0 && count <= limit;
}
```

**预测：** 写下四次调用的结果，并在代码中标出声明、定义、调用、形参和实参。

**运行：** 用前面的编译命令执行。逐行比较结果；不要只检查“程序是否退出”。

**改动：** 把规则改为 `1..limit`，只改函数中的判定条件。重新预测这四次调用，再编译运行。随后额外测试 `isCountValid(0, 0)`，比较两种规则的差异。

**检查与中文解析：** 原规则输出依次为 `true、true、false、false`；改成从 `1` 开始后依次为 `false、true、false、false`。对于 `(0, 0)`，原规则为真，改动后为假。函数返回的是一个判定结果，`std::boolalpha` 只是把布尔输出显示为文字，不会改变判断。这个小函数让调用者只描述“检查计数”，将边界规则放在同一个位置。

完成标准：能解释为什么需要测试 `0`、`limit`、`-1` 和 `limit+1`，而不是只用一个中间值。

## CH02-P02：测量换算与默认参数

场景：把测量到的像素长度乘以给定尺度，得到毫米长度。练习尺度为 `0.25 mm/px`。

```cpp
#include <iomanip>
#include <iostream>

double pixelsToMm(double pixels, double mmPerPixel = 0.25);

int main() {
    double defaultLength = pixelsToMm(40);
    double explicitLength = pixelsToMm(40, 0.10);
    std::cout << std::fixed << std::setprecision(2);
    std::cout << defaultLength << '\n';
    std::cout << explicitLength << '\n';
}

double pixelsToMm(double pixels, double mmPerPixel) {
    return pixels * mmPerPixel;
}
```

**预测：** 写出两次调用分别采用的尺度以及两行输出。

**运行：** 保存为 `p02.cpp`，编译运行。`std::fixed` 和 `std::setprecision(2)` 让输出保留两位小数，方便比较。

**改动：** 只把声明中的默认尺度改为 `0.50`；先预测输出，再运行。随后给第一次调用显式补上 `0.25`，再次比较。

**检查与中文解析：** 起初输出为 `10.00`、`4.00`；默认尺度改成 `0.50` 后，只有第一行变成 `20.00`。给第一处调用明确传入 `0.25` 后，第一行又回到 `10.00`。显式实参覆盖的是“本次省略时才使用的默认选择”。不要在函数定义中重复写默认值。

边界再查一次：`pixelsToMm(0)` 应为 `0.00`。当前函数只演示换算，不会拒绝负长度或错误尺度；实际使用前应约定输入条件。视觉项目里，尺度变化会直接影响测量结果，因此要记录单位和尺度来源。

完成标准：能说出“默认值改变会影响哪些调用”，并在变量说明中写清 `px` 与 `mm`。

## CH02-P03：观察重载选择和编译歧义

场景：对两个数取较大值，分别支持整数计数与浮点测量。为观察调用版本，函数暂时打印一行标记。

```cpp
#include <iostream>

int larger(int a, int b) {
    std::cout << "int version\n";
    return a > b ? a : b;
}

double larger(double a, double b) {
    std::cout << "double version\n";
    return a > b ? a : b;
}

int main() {
    int count = larger(7, 3);
    double length = larger(7.0, 3.5);
    std::cout << count << ' ' << length << '\n';
}
```

**预测：** 写出两个调用各选哪个版本，以及完整输出顺序。

**运行：** 保存为 `p03.cpp`，编译运行。这里使用两条独立的赋值语句，所以可以按语句顺序追踪。

**改动：** 将第二次调用改为 `larger(7, 3.5)`，先判断是否能编译，再运行编译命令。读完歧义报错后，把它改成 `larger(7.0, 3.5)` 或 `larger(static_cast<double>(7), 3.5)`，重新编译。

**检查与中文解析：** 原程序先打印 `int version`，再打印 `double version`，最后打印 `7 7`。混合类型版本对这里的两个候选函数没有唯一更优匹配，因此编译失败；这不是程序运行时才发生的故障。`double` 变量接收结果，并不等于编译器会据此选择返回 `double` 的重载。显式统一实参类型后，调用重新变得明确。

完成标准：能解释两个重载的区别来自参数列表，并知道编译失败后不应直接运行旧的 `p03` 来“验证修改”。观察结束后可以删掉函数内部的版本打印，让计算函数只返回结果。

## CH02-P04：把量程端点排好，比较按值与引用

场景：用户可能把量程写成 `8..3`，我们希望规范成 `3..8`。先观察下面的函数为什么没有改变调用者。

```cpp
#include <iostream>

void normalizeRange(int low, int high) {
    if (low > high) {
        int temporary = low;
        low = high;
        high = temporary;
    }
    std::cout << "inside: " << low << ' ' << high << '\n';
}

int main() {
    int low = 8;
    int high = 3;
    normalizeRange(low, high);
    std::cout << "outside: " << low << ' ' << high << '\n';
}
```

**预测：** 分别写出 `inside` 和 `outside` 的值；明确这两个输出读取的是哪一对变量。

**运行：** 保存为 `p04.cpp`，编译运行。

**改动：** 只把形参改成 `int& low, int& high`。再次预测并运行，然后分别测试初值 `(3, 8)`、`(-3, -8)`、`(5, 5)`。最后另用一个变量 `value=5`，测试 `normalizeRange(value, value)`。

**检查与中文解析：** 按值版本打印 `inside: 3 8`、`outside: 8 3`；引用版本两行都为 `3 8`。前者交换的是副本，后者通过引用修改原变量。`(-3, -8)` 规范后应为 `(-8, -3)`；已排好的端点、相等端点、同一变量传入两次都应保持正确。

临时变量用于保留旧值；若直接写 `low=high; high=low;`，两端可能变成同一个值。这里的代码是配套练习，引用参数的阅读起点为 [PDF 第 64 页 2.5](../../../../导入教材.md#这两份文件为什么不在仓库里)。

完成标准：能在纸上分别画出按值版本的两对变量，以及引用版本所绑定的一对原变量。

## CH02-P05：追踪组合数调用，不猜表达式顺序

场景：从 6 个候选特征中选 2 个，暂时只关心无顺序的组合数量。它对应原书 [PDF 第 59–60 页](../../../../导入教材.md#这两份文件为什么不在仓库里) 的组合数主线。

```cpp
#include <iostream>

int fact(int n) {
    int result = 1;
    for (int i = 1; i <= n; ++i) {
        result *= i;
    }
    std::cout << "fact(" << n << ") = " << result << '\n';
    return result;
}

int combinations(int n, int k) {
    int numerator = fact(n);
    int left = fact(k);
    int right = fact(n - k);
    int denominator = left * right;
    return numerator / denominator;
}

int main() {
    int ways = combinations(6, 2);
    std::cout << "ways = " << ways << '\n';
}
```

**预测：** 先不运行，画出 `main → combinations → fact` 的调用卡片，填上三个阶乘结果和组合数结果。每一次 `fact` 都单独记录形参 `n` 和局部变量 `result`。

**运行：** 保存为 `p05.cpp`，编译运行。逐行检查日志是不是 `720、2、24`，最后是否为 `15`。

**改动：** 在保持这几个固定小输入的前提下，暂时把 `combinations` 改成下面的一行版本：

```cpp
return fact(n) / (fact(k) * fact(n - k));
```

运行后记录观察到的日志顺序，再恢复临时变量版本。继续测试 `(5, 0)`、`(5, 5)`、`(0, 0)`。本题为调用追踪而设，手工修改时先限于 `0 <= k <= n <= 7`，使这些阶乘在标准要求的最小 `int` 范围内也能表示。

**检查与中文解析：** 三个边界组合数都应为 `1`。一行版本中，三个 `fact` 调用的先后不能假设从左到右；一次或多次观察到某种顺序，都不能证明它被语言保证。这里各个函数只用自己的形参计算，调用先后不改变这些小输入的答案。恢复三条调用语句后，日志顺序才由语句顺序明确规定。[C++ 工作草案：执行顺序](https://eel.is/c++draft/intro.execution)

完成标准：能说明为什么使用临时变量追踪更清楚，并解释每次 `fact` 都有自己的局部变量。不要用越界阶乘的输出研究调用顺序；先保证运算本身有效。

## CH02-P06：给阶乘加输入检查和乘法前检查

场景：Linux 命令行工具收到一个阶乘输入。它必须区分“读入失败”“输入为负”和“结果放不进 `int`”，不能静默给出错误数字。

```cpp
#include <iostream>
#include <limits>

bool tryFactorial(int n, int& value) {
    if (n < 0) {
        return false;
    }

    int result = 1;
    for (int i = 1; i <= n; ++i) {
        if (result > std::numeric_limits<int>::max() / i) {
            return false;
        }
        result *= i;
    }
    value = result;  // 仅在完整计算成功时修改输出参数
    return true;
}

int main() {
    int n = 0;
    if (!(std::cin >> n)) {
        std::cerr << "expected an integer\n";
        return 1;
    }
    if (n < 0) {
        std::cerr << "n must be non-negative\n";
        return 1;
    }

    int answer = -1;
    if (!tryFactorial(n, answer)) {
        std::cerr << "factorial exceeds int range\n";
        return 2;
    }
    std::cout << answer << '\n';
    return 0;
}
```

**预测：** 对单独输入 `0`、`1`、`6`、`-1`、`abc`，分别写出程序经过哪一条路径。再查看本机 `std::numeric_limits<int>::max()`，判断 `13` 是否会被拒绝。

**运行：** 保存为 `p06.cpp`，编译后逐个输入。也可以把一次输入通过管道交给程序：

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic p06.cpp -o p06
```

确认编译成功后再执行：

```bash
printf '6\n' | ./p06
```

紧接程序运行后使用 `echo $?`，可查看退出状态。成功为 `0`，两种输入错误为 `1`，阶乘超出范围为 `2`。脚本随后可以根据退出状态判断这次计算是否成功。

**改动：** 临时在 `main` 中把输入部分换成下面的固定检查，观察失败调用是否保留了原来的输出变量：

```cpp
int answer = 123;
bool ok = tryFactorial(-1, answer);
std::cout << std::boolalpha << ok << ' ' << answer << '\n';
```

随后恢复原来的 `main`，不要保留两个 `main`。对本机确定会超出阶乘范围的非负数再做一次同类检查，例如常见 32 位 `int` 上的 `13`。

**检查与中文解析：** `0` 和 `1` 输出 `1`，`6` 输出 `720`；负数与非整数输入走各自的错误路径。在 `int` 上限为 `2147483647` 的环境中，`13` 被拒绝。固定检查输出 `false 123`：函数先在局部变量里计算，成功时才通过引用提交结果。

检查必须放在 `result *= i` **之前**。因为循环中 `i > 0`，且 `result` 为正，所以 `result > max / i` 能判断下一次乘法是否超出上限，而不用先执行危险乘法。不能先乘出溢出结果，再靠结果的正负判断。`int` 有符号溢出属于未定义行为。[C++ 工作草案：表达式的可表示范围](https://eel.is/c++draft/expr.pre)

本练习只要求读入一个整数；像 `6abc` 这样的输入会先成功提取整数前缀 `6`。若工具要求整行只能有一个整数，还需要另外检查剩余输入，不能把这份入门示例当作完整命令行解析器。

完成标准：能解释两个返回通道的职责：`bool` 表示成功与否，`int& value` 在成功时交回数值；同时能说明 `main` 的退出状态怎样被 Linux shell 使用。
