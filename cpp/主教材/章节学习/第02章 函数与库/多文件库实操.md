# 多文件库：写函数，主程序负责调用

第10、11题由几个文件合作完成。**日常只编辑“我的作答”里的库 `.cpp`，保存后直接运行“本题：检查作答”**，无需来回切主程序。Windows 与 Ubuntu 使用同一份源文件。

| 文件 | 职责 | 本题需要填写吗 |
| --- | --- | --- |
| `我的作答/combinatorics.h` 或 `calendar.h` | 声明函数名称、参数、返回类型，是调用约定 | 已给定，阅读即可 |
| `我的作答/combinatorics.cpp` 或 `calendar.cpp` | 实现函数，BEGIN/END 标出补全处 | **在这里填写** |
| `work.cpp` | main 读取输入、调用你写的函数、输出结果 | 已给定，阅读即可 |

工作台右侧默认显示填写的库，通过“查看本题文件”可看声明和主程序。“打开本题作答”会打开本题目录并定位库实现，运行与检查仍使用给定的 work.cpp。

## 每次做题只走这几步

1. 从[第10题：组合数学库](课后习题/第10题 组合数学库/README.md)或[第11题：日历库](课后习题/第11题 日历库/README.md)读任务，先手算一组结果。
2. 打开 `我的作答` 中的库 `.cpp`，逐个补函数体，删掉对应区域的占位 throw；保持函数声明一致。
3. 保存后在当前库文件运行 **“本题：检查作答”**。工具会找到同题 work.cpp，把自己的库一起编译；不会暗中链接参考答案。在声明 `.h` 或本题 README 启动也能定位这道题。
4. “本题：运行作答”只运行；要使用 input.txt，选“本题：用样例输入运行”。网页“运行本题”会使用已有的 input.txt。

参考实现位于题目外层，与“我的作答”分开；不要覆盖自己的文件后当作完成。

## 为什么只 include 头文件还不够

include 让编译器知道函数声明。库 cpp 给出定义，链接阶段把调用与定义连起来。学习区已登记准确的源文件组合，日常不用手写编译命令。

- **未定义引用 / undefined reference**：检查声明与定义的名称、参数、命名空间是否一致，以及是否链接库源码。
- **重复定义 / multiple definition**：通常是同一份实现加入两次，或额外写了 main。
- **补全区尚未完成**：有函数仍保留占位代码；不是编译失败，也不会计为样例通过。

想观察编译和链接过程时，在自己的临时实验目录使用 CMake 或手动编译，不改本题主程序和参考文件。Linux 的构建教学在学习区“环境配置教程”的 CMake 章节中。
