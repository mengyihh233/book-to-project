# 第16章 项目：二叉搜索树索引

> **要干什么：** 把一串整数依次插进二叉搜索树，报告它的形状（高度、结点数、前序、中序），再按查询回答「这个数在第几层」。
> 这题**不给骨架**，从 `#include` 开始全自己写。README 里有一组示例，**判分用的是另外 7 组**看不见的输入。

## 1 · 需求

标准输入：

```text
6
8 3 10 1 6 14
2
6 7
```

| 行 | 内容 |
| --- | --- |
| 第 1 行 | `n`（0 ≤ n ≤ 100000）个结点 |
| 第 2 行 | `n` 个整数，**按这个顺序插入** |
| 第 3 行 | `m`（0 ≤ m ≤ 100000）次查询 |
| 第 4 行 | `m` 个要查询的整数 |

输出先 4 行摘要，再每个查询一行：

```text
高度 3
结点 6
前序 8 3 1 6 10 14
中序 1 3 6 8 10 14
深度 6 3
未找到 7
```

- 查到：`深度 值 层数`
- 查不到：`未找到 值`
- 空树时：`高度 0`、`结点 0`，`前序` 和 `中序` 后面**没有值**

## 2 · 关键要求

1. 自己定义结点（一个值 + 左指针 + 右指针），用 `new` 搭树，结束前释放。
2. 插入规则：小走左、大走右、**相等直接忽略**（不新建结点）。
3. 查深度用「从根往下走」的查找，**别为了一个查询遍历整棵树**。
4. 前序/中序用递归写；500 个递增的数要能跑完（别用固定大小数组存树）。

> 自动判分只看输入输出，**看不出你用了什么结构**。拿 `std::map` 冒充也能过，但这一章练的就是指针和递归，别骗自己。

## 3 · 规则与边界

| 情况 | 要求 |
| --- | --- |
| 重复值 | 忽略，不新建结点，不报错 |
| 空树（n = 0） | 高度 0、结点 0；`前序`/`中序` 只有标签 |
| m = 0 | 只输出 4 行摘要 |
| 根结点 | 深度算 **1** |
| 查不到 | `未找到 值` |
| 负数 | 正常参与比较（`-7 < -2`） |
| n < 0 或 n > 100000 | 返回 2，**stdout 必须为空** |
| m < 0 或 m > 100000 | 返回 2，stdout 为空 |
| 数字个数不够 | 返回 2，stdout 为空（**先读完再打印**） |

## 4 · 验收清单

- [ ] 上面那组输入 → 4 行摘要 + `深度 6 3` + `未找到 7`
- [ ] `0` 和 `0` → `高度 0`、`结点 0`，后两行只有标签
- [ ] 5 个都是 `3` → 高度 1、结点 1、前序 `3`、中序 `3`
- [ ] 递增 500 个数 → 高度 500（退化成一条链）
- [ ] m = 0 → 只有 4 行，没有多余空行
- [ ] n = -1 → 返回 2，屏幕上什么都没有
- [ ] m = 2 但只给 1 个查询 → 返回 2，屏幕上什么都没有

## 5 · 哪个是判分的

**只有一个：这里（或 VS Code）的「检查本题」。** 7 组隐藏输入，逐字比对 `stdout`，同时比对退出码。

两件事都会算错：

1. 输出少一个空格、多一个空行（比如空树时多打一个换行）。
2. 非法输入时先打了半份报表再返回 2 —— 这类也算错。

## 6 · 做完的标准

1. 中序遍历为什么一定是升序？什么情况下不是升序？
2. 同样的 n 个数，换插入顺序，树高最多能差多少？最坏是多少？
3. 查找深度用循环和用递归，哪个更省栈？
4. 500 个递增数插进来，递归调用的深度是多少？换成 10 万个呢，会出什么事？

## 7 · 扩展（可选）

1. 每个结点额外存「左子树结点数」，用它做第 k 小查询。
2. 支持删除结点（叶子 / 只有一个孩子 / 两个孩子，三种情况分开写）。
3. 把中序遍历改成迭代写法（自己维护一个显式栈）。
