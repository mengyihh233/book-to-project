# 解析：词频统计

> 先自己写一遍再看。这里讲判断，不贴整份代码（完整实现见 `reference.cpp`）。

## 关键判断一：在哪里切词

三种写法，差别很大：

| 写法 | 问题 |
| --- | --- |
| 用 `cin >> word` 直接读 | 只按空白切，`foo-bar` 会算成一个词，与「非字母是分隔符」冲突 |
| 整段读进来再 `split` | 要先处理换行，还得多存一份全文（1 GB 文本会炸） |
| **逐行读、逐字符扫描** | 内存只占一行；行尾 flush 一次即可 |

正确做法是第三种：一次只看一个字符，是字母就攒进当前词，不是字母就结算。

```cpp
for (char ch : line) {
    if (isalpha(ch)) word += tolower(ch);
    else if (!word.empty()) { /* 结算 word，然后清空 */ }
}
// 行末别忘了再结算一次
```

**行末那次结算最容易漏。** 漏了的话，每行最后一个词会丢失，而且只有「词刚好在行尾」时才错，很难发现。

## 关键判断二：两种「空」不是一回事

| 输入 | 含义 | 正确行为 |
| --- | --- | --- |
| 0 字节 | 连停用词行都没有 → 输入不完整 | 返回 2，stdout 空 |
| `\n`（一个空行） | 停用词为空，正文为空 → 合法的空任务 | 返回 0，stdout 空 |

区分方法只有一个：**看第一次 `getline` 有没有成功**。

```cpp
std::string stopLine;
if (!std::getline(std::cin, stopLine)) return 2;   // 一个字节都没有
// 读到了（哪怕是空行）就是合法输入，继续
```

很多写法在这里出错：先 `while (getline(...))` 收集全部行，再判断「有没有内容」——这样两种空会被合并成一种。

## 关键判断三：排序要两个条件

只按次数降序，次数相同的元素顺序取决于排序算法和输入顺序，**同一份输入可能两次跑出不同结果**。这类 bug 在自动判分里表现为「有时过有时不过」。

```cpp
if (a.count != b.count) return a.count > b.count;
return a.word < b.word;   // 第二个条件不能省
```

`std::sort` 不保证稳定，所以不能指望「次数相同的保持原顺序」，必须显式写字典序。

## 关键判断四：截断放在排序之后

先排完再取前 10，不要「边统计边维护 top10」——后者是对的，但要多写一个最小堆，容易写错边界。先用最简单的写法跑通，再考虑优化。

`counts.resize(10)` 之前要判断 `size() > 10`，否则不足 10 个词时会把 `vector` 撑大，输出空行。

## 常见错法

| 现象 | 原因 |
| --- | --- |
| 每行最后一个词丢了 | 行末没结算 |
| `foo-bar` 算成一个词 | 只按空白切，没按字符扫描 |
| `The` 和 `the` 分开统计 | 忘记统一转小写 |
| 空输入返回 0 | 没检查第一次 `getline` |
| 输出 10 行但顺序不稳 | 排序缺字典序第二条件 |
| 输出多了提示语 | 把交互提示写进了 stdout；提示应该写 stderr 或干脆不写 |

## 如果要做扩展

1. **中文分词**：UTF-8 里一个汉字占 3 字节，逐字节判断 `isalpha` 会对中文返回 false，所以现在的实现会把中文全当分隔符。要支持中文得按 UTF-8 码点解码，不能用 `char` 循环。
2. **1 GB 文本**：当前实现内存只占一行 + 词表，瓶颈在词表本身。词表可能上百万条，那时要把 `vector` 换成 `unordered_map`，并且不能全排序（用堆取 top 10）。
3. **可配置词数**：把 `10` 换成读进来的变量即可，但注意「不足 N 个」和「超过 N 个」两种情况都要处理。
