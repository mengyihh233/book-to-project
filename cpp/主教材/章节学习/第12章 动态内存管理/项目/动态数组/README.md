# 第12章 项目：动态数组

> **要干什么：** 手写一个会扩容的动态数组，边读边存，最后报告统计。
> 这题**不给样例、不给骨架**，从 `#include` 开始全自己写。

## 1 · 需求

标准输入：

```text
5
1 2 3 4 5
```

- 第一行 `n`（1 ≤ n ≤ 100000）；
- 第二行 n 个整数。

输出四行：

```text
个数 5
总和 15
最大 5
扩容 3
```

- `个数` 是实际存入的元素个数；
- `总和` 用 `long long`；
- `最大` 是最大值；
- `扩容` 是**容量增长了几次**，规则见下。

## 2 · 扩容规则（必须严格照做）

- 初始容量 **1**，大小为 0；
- 每次 `push` 前检查：**大小 == 容量** 就先扩容；
- 扩容 = **容量翻倍**，把旧数据复制到新数组，**释放旧数组**；
- 每扩容一次，计数 +1。

所以：

| n | 容量变化 | 扩容次数 |
| --- | --- | --- |
| 1 | 1 | 0 |
| 2 | 1→2 | 1 |
| 5 | 1→2→4→8 | 3 |
| 8 | 1→2→4→8 | 3 |
| 9 | 1→2→4→8→16 | 4 |

## 3 · 关键要求

**必须自己 `new[]` / `delete[]`**，不许用 `std::vector`。
析构函数里要释放；扩容时旧数组也要释放。

自动判分看不出内存有没有泄漏——**但这一章练的就是所有权，漏了等于没做。**

## 4 · 边界

| 情况 | 要求 |
| --- | --- |
| `n` < 1 或 > 100000 | 返回 2 |
| 数据不足 n 个 | 返回 2 |
| 元素有负数 | 正常处理，`最大` 按实际最大值 |

## 5 · 验收清单

- [ ] `5` + `1 2 3 4 5` → 个数 5，总和 15，最大 5，扩容 **3**
- [ ] `1` + `7` → 个数 1，总和 7，最大 7，扩容 **0**
- [ ] `2` + `3 1` → 最大 3，扩容 **1**
- [ ] `8` + 1..8 → 扩容 **3**（8 正好装满，不再扩容）
- [ ] `9` + 1..9 → 扩容 **4**
- [ ] `0` → 返回 2
- [ ] `3` + 只有两个数 → 返回 2

**第 4 条和第 5 条是关键**：n=8 和 n=9 只差一个元素，扩容次数差 1。

## 6 · 哪个是判分的

**只有一个：这里（或 VS Code）的「检查本题」。** 7 组看不见的输入，逐字比对。

## 7 · 做完的标准

1. 「大小」和「容量」为什么要分开？只用一个变量会怎样？
2. 扩容时为什么必须复制旧数据？不复制会怎样？
3. 为什么扩容后要 `delete[]` 旧数组？漏了会怎样？
4. 如果每次扩容只加 1 个容量，n=100000 要复制多少次？

## 8 · 扩展（可选）

1. 改成 1.5 倍扩容，比较扩容次数。
2. 加 `pop_back()`，缩容到 1/4 时容量减半。
3. 用 `valgrind`（Linux）或 `Application Verifier`（Windows）确认没有泄漏。
