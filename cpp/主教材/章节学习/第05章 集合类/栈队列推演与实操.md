# 栈和队列：画出顺序再写代码

对应原书第5章12—15题，使用标准库容器适配。队列的front对应原书peek，pop只删除而不返回元素；先读top/front，再pop。空栈、空队列不能直接取元素。

| 容器 | 加入 | 读取并移除 | 学习问题 |
|---|---|---|---|
| stack | push | top后pop | 最后来的为什么最先出去？ |
| queue | push | front后pop | 为什么最新记录不能越过旧记录？ |

## 先追踪三个状态

第12题输入10、20、30、0，栈从底到顶依次为[10]、[10,20]、[10,20,30]；0不入栈，输出30、20、10。每次pop后剩余元素顺序不变。若漏掉终止0，本区输入协议应报错，不输出半份答案。

第13题队列从队首到队尾为A、B、C，逐项出队压栈后栈顶是C；再依次出栈入队，队首变C。不要一边原地出队入队却没有剩余数量控制，那可能一直转圈。反转两次恢复原队列是一个性质检查，但还需用三个不同元素验证一次反转的顺序。

第14题([)]的左右括号数量相等，但遇到)时栈顶是[，所以不匹配。只用三个计数器不能保证嵌套顺序。要把“读到右括号时有对应栈顶”和“结束后栈空”分开检查。此题忽略普通字符，不理解C++引号、转义和注释。

## roll方向为什么容易反

用A B C D表示栈底到栈顶，D在顶。

| 操作 | 手算结果（底→顶） | 检查重点 |
|---|---|---|
| roll(4,1) | D A B C | 原栈顶D移到选中段底部 |
| roll(3,2) | A C D B | 底部A完全不变 |
| roll(2,4) | A B C D | 4%2=0，整圈后恢复 |
| roll(0,k) | 原样 | 先处理0，避免除0 |

弹出到向量后，向量的方向是顶→底，和表中相反。因此不能只记“向左/向右旋转”，应先写出容器内的真实顺序。k可以很大，先取模再操作；不做k次循环。

## 四步实操

1. 在自己的notes.md画操作轨迹，标出栈顶、队首，不看解析。
2. 自己在work.cpp实现函数和main；输入协议见每题README。
3. 每题写正常、边界、错误各一个输入，再用当前作答检查入口。
4. 找一个“看起来合理却错”的实现：括号只计数、roll方向相反、队列漏掉空字符串、0当成数据。用最小反例击中它。

## 接到机器视觉和Linux

机器视觉批处理可以把待处理图片看成队列：顺序读取，失败的图记录到失败清单后继续。撤销操作可用栈保存历史，但不能只保存计数，还要保存足够恢复的状态。这是理解数据结构的类比，本轮没有把检测器改成并发队列。

Linux里tac可以倒转逐行记录；若文件名含换行，逐行协议就无法区分记录，仍需NUL分隔。第13题的文本协议只适用于不含换行的字符串，不应拿它直接代替安全文件名清单。

[视觉报告核对实操](../../../../linux/projects/dataset-audit/视觉报告核对.md)把现有机器视觉JSON结果变成CSV，再用Linux管道汇总；先核对数据约定，再谈算法结论。
