# 用同一批顾客比较两种队列

对应原书第5章16、17题。图5-5在PDF166—168页，习题在PDF190页。原书使用随机到达和随机服务时长；本区把它们改为明确的逐秒输入，以便手算、重复运行和公平对照。这是输入适配，不是声称与原书同一个随机种子会生成同样结果。

## 先明确模型，再写循环

每秒至多到达一人。第16题每个收银员一条队列，顾客按当前等待人数选择最短队列；并列选编号小者，入队后不换队。服务中的人已经出队，不算等待队列长度。第17题共用一条FIFO队列，空闲收银员按编号顺序接人。

原书图5-5代码的关键顺序是：先处理到达，再对每个收银员执行busy倒计时；只有本秒原先不忙，才进入else-if分支接下一人。因此服务时长1的人在t=0开始，t=1完成，收银员要到t=2才能接下一位。本区明确保留这条规则，不默默替换成另一种离散事件模型。

## 同一输入，两个结果

8秒、2个收银员：第0、1、2、3秒各到一位顾客，所需服务时长分别3、1、2、1；之后无到达。工作台两题都有逐秒实验，可先预测，再点“下一秒”。

| 时刻 | 各自队列发生的主要事件 | 共用队列发生的主要事件 |
|---|---|---|
| 0 | 顾客1在1号开始 | 同左 |
| 1 | 顾客2选1号等待，2号仍空闲 | 顾客2在2号开始 |
| 2 | 顾客3在2号开始 | 顾客2完成，顾客3等待 |
| 3 | 顾客1完成，顾客4进入2号等待 | 顾客1完成，顾客3在2号开始 |
| 4 | 顾客2在1号开始，顾客3完成 | 顾客4在1号开始 |
| 5 | 顾客2完成，顾客4在2号开始 | 顾客3、4完成 |
| 6 | 顾客4完成 | 均空闲 |
| 7 | 均空闲 | 均空闲 |

各自队列total_wait=5、queue_area=5；共用队列均为2。四人均已开始，平均等待分别1.25与0.5秒；8秒平均等待队长分别0.625与0.25。不要把这一个例子说成任意策略、输入或统计口径下的普遍保证。

第1秒各自排队出现“2号空闲但顾客2仍在1号队列”，来自并列选小编号且不计服务中人数的约定。若改为优先空闲或按预计剩余工作量选择，是另一个策略，需明确标注后再比较，不能悄悄改题。

## 三个计数别混淆

arrived是到达人数；started对应原程序开始接待时累加的nServed；finished是服务真正完成的人数。仿真到T秒就停止，不额外排空。

- arrived = started + waiting。
- started = finished + busy。
- total_wait只累计已经开始服务的顾客等待时间；尚未开始的人未计入该均值。
- queue_area为每秒处理完成后的等待人数之和，不含正在服务的人；mean_queue=queue_area/T。

分母为0时，本区输出0作为展示约定，不表示空数据具有统计均值。短时运行时，平均等待低可能只是有很多人仍没轮到，必须同时看waiting和finished。

## 独立动手

1. 用1位收银员运行两题，结果应完全相同。
2. 用空轨迹、无到达、只在最后一秒到达和服务长于仿真时长的输入检查边界。
3. 在notes.md先写每秒顾客顺序与收银员剩余时长，再实现自己的work.cpp。
4. 把服务时长改成1、1、1、1，预测差异是否改变；再缩短T，说明“已开始”与“已完成”的区别。
5. 为第17题写出利弊：共用队列按到达顺序接待，减少被困在某条长队的机会；但空间组织、分流和特殊服务需求可能另有限制，不能仅凭平均值评价。
