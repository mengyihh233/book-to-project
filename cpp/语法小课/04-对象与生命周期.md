## 结构、对象与成员

原书联系：[6.1.1 将 Point 定义为结构类型](../../workbench/chapter.html?chapter=6#page=193)。原书主题的中文提炼，示例与实操为自编配套。

把相关数据组合成一个类型，可以让程序直接表达问题中的事物。原书用二维点说明：Point是类型，一个具体的p是对象，x与y是它的成员。通过p.x访问这个对象的x。

struct和class都能定义类型、成员和方法；最直接的默认区别是struct成员默认public，class成员默认private。先用简单记录结构理解“类型—对象—成员”，再学习封装与不变量。

```cpp
#include <iostream>
struct Point { int x; int y; };
int main() {
    Point p{2, 3};
    std::cout << p.x << " " << p.y << '\n';
}
```

**容易混淆：** 类型定义结尾要写分号；两个对象的普通成员各自保存。

## 类、构造与封装

原书联系：[6.1.2 将 Point 定义为类](../../workbench/chapter.html?chapter=6#page=194)。原书主题的中文提炼，示例与实操为自编配套。

类把数据和操作组织在一起，构造函数负责建立初始状态。不变量是每次公开操作后都必须成立的条件，例如账户余额不能为负。

private隐藏内部表示，public定义使用方式。const成员函数表达只读查询；隐藏字段不等于可以忽略输入验证。

```cpp
#include <iostream>

int main() {
    class Counter {
        int value_ = 0;
    public:
        void add() { ++value_; }
        int value() const { return value_; }
    };
    Counter c; c.add();
    std::cout << c.value() << '\n';
}
```

**容易混淆：** public是外部可调用接口，private成员不能在main中直接访问。

### 先预测

查询函数后面的const主要表达什么？

1. 不能读取任何字段
2. 承诺不通过this修改对象的普通成员状态
3. 返回值必须是const int

声明只读查询成员函数

## 构造函数：对象从正确状态开始

原书联系：[6.3.4 为 Rational 类定义构造函数](../../workbench/chapter.html?chapter=6#page=208)。原书主题的中文提炼，示例与实操为自编配套。

构造函数与类同名，在对象创建时建立状态，没有返回类型。不要先创建一个无法使用的对象，再要求调用者记住补齐若干步骤；尽量让构造成功就意味着基本约定成立。

成员初始化列表在进入构造函数体前初始化成员。原书有理数类的核心之一就是从一开始统一表示；这里先用计数器理解机制，再回到更复杂的不变量。

```cpp
#include <iostream>
class Counter {
    int value_;
public:
    explicit Counter(int start) : value_(start) {}
    int value() const { return value_; }
};
int main() {
    Counter c(3);
    std::cout << c.value() << '\n';
}
```

**容易混淆：** 构造函数不写返回类型；给成员赋值和成员初始化发生在不同阶段。

## 方法、封装与不变量

原书联系：[6.3.5 为 Rational 类定义方法](../../workbench/chapter.html?chapter=6#page=209)。原书主题的中文提炼，示例与实操为自编配套。

成员函数也叫方法，负责对对象执行有意义的操作。public接口给调用者使用，private保存内部表示；调用者依靠接口的约定，而不是直接改每个字段。

不变量是对象在公开操作完成后应一直满足的条件。设计账户类时，拒绝一次取款后余额也应保持原值。先写清允许与拒绝的行为，再实现方法；const查询方法表达不修改普通成员状态。

```cpp
#include <iostream>
class Counter {
    int value_ = 0;
public:
    void add() { ++value_; }
    int value() const { return value_; }
};
int main() {
    Counter a, b;
    a.add();
    std::cout << a.value() << " " << b.value() << '\n';
}
```

**容易混淆：** const对象只能调用适用的const查询方法；不要为查询顺手改变对象状态。

### 先预测

a.add()之后，b的值一定跟着改变吗？

1. 会，类只有一份普通成员数据
2. 不会，这里两个对象各有自己的状态
3. 只有变量名相同才改变

## 指针、地址与生命周期（按需补充）

原书联系：[11.1 内存结构](../../workbench/chapter.html?chapter=11#page=335)。原书主题的中文提炼，示例与实操为自编配套。

指针保存地址，&取得对象地址，*解引用访问对象。指针可以为空；解引用前必须确认它指向仍然存活的有效对象。

nullptr表示空指针，但非空也不保证有效。函数返回后局部变量会结束生命周期，不能把它的地址带出去继续使用。

```cpp
#include <iostream>

int main() {
    int value = 3;
    int* p = &value;
    *p = 8;
    std::cout << value << '\n';
}
```

**容易混淆：** 指针可能为空；解引用前确认有效，也不能保留已销毁对象的地址。

*p = 8修改了什么？

2. p所指向的value
3. 一个自动生成的副本

## RAII与unique_ptr（按需补充）

原书联系：[12.1 动态分配和堆](../../workbench/chapter.html?chapter=12#page=362)。现代C++补充，链接为关联原书主题，并非原书同名接口。

RAII把资源释放绑定到对象生命周期，让正常返回和异常退出都能清理资源。优先用标准容器与资源管理对象，而不是手写new/delete配对。

unique_ptr表示独占所有权，不能普通复制，可用std::move转移。move表达允许移动，不保证所有类型的源对象都会自动变空；unique_ptr转移后源为空是该类型的约定。

```cpp
#include <iostream>
#include <memory>
#include <utility>

int main() {
    auto p = std::make_unique<int>(7);
    auto q = std::move(p);
    std::cout << (p == nullptr) << " " << *q << '\n';
}
```

**容易混淆：** unique_ptr表示独占所有权，不能复制；转移后不要假定原指针仍拥有对象。

## 异常与错误处理（按需补充）

原书联系：[第4章：输入与错误处理的关联](../../workbench/chapter.html?chapter=4)。现代C++补充，链接为关联原书主题，并非原书同名接口。

异常把无法在当前层解决的失败交给调用层。throw抛出异常，try/catch处理；捕获标准异常通常使用const引用。

异常处理不代替输入验证。要知道哪些操作可能抛出、失败后对象是否仍有效；不要catch后假装处理成功。

```cpp
#include <iostream>
#include <string>
#include <stdexcept>

int main() {
    try {
        auto value = std::stoi("abc");
        std::cout << value << '\n';
    } catch (const std::invalid_argument&) {
        std::cout << "invalid input\n";
    }
}
```

**容易混淆：** 异常处理应恢复约定或明确失败；捕获异常并不等于操作已成功。
