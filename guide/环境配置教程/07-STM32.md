# STM32F103C8T6 + ST-Link：另一种目标平台

你指定的硬件是STM32F103C8T6与ST-Link。原学习区在D:/STM32-Learning，完整第一课见该目录00-Guide/使用教程.md；本篇解释环境分工，不声称已验证实体接线或烧录。

## 工具各自负责什么

| 工具 | 职责 |
|---|---|
| arm-none-eabi-gcc / g++ | 为ARM裸机交叉编译，不是PC g++ |
| 启动文件、链接脚本 | 定义复位入口、栈和Flash/RAM布局 |
| CubeMX | 选择芯片、引脚、时钟并生成初始化工程 |
| CubeProgrammer | 通过探头连接、下载和校验固件 |
| ARM GDB与GDB Server | 调试链路，不能用PC GDB代替 |
| ST-Link | 连接目标芯片的调试/下载探头 |

本机已读到ARM工具链路径D:/DevTools/arm-gnu-toolchain-14.3.rel1-mingw-w64-x86_64-arm-none-eabi，bin/arm-none-eabi-gcc.exe存在；CubeMX为D:/STM32CUBE/STM32CubeMX.exe。CubeProgrammer与GDB Server的安装、驱动和实际路径仍需按本机情况确认，不能仅凭装了VS Code扩展认定全部可用。

## 第一步：只验证编译

现有01-LED是寄存器入门工程，不依赖HAL。VS Code选任务“STM32: 编译 LED”，或：

```powershell
pwsh -NoProfile -File 'D:/STM32-Learning/01-LED/build.ps1'
```

看build/led.elf、led.hex、led.bin是否生成。ELF供调试，HEX含地址，BIN是原始字节。编译成功仅说明软件链路，不证明开发板在运行。

## 第二步：接线与下载

先按板子和探头资料确认3.3V供电、共地、SWDIO/PA13、SWCLK/PA14；VTref与电源输出不是同一个概念。沿用原教程逐项核对，不在不清楚接口时猜接线。

通过[ST官方CubeProgrammer](https://www.st.com/en/development-tools/stm32cubeprog.html)确认探头与芯片连接，再下载HEX并校验。BIN需要正确起始地址，原工程为0x08000000。下载会改变目标板现有固件，需要保留的程序先处理备份。

## 第三步：调试与HAL工程

ARM GDB需要对应GDB Server和探头驱动。先明确采用[ST官方VS Code工作流](https://www.st.com/content/st_com/en/campaigns/stm32-vs-code-extension-z11.html)还是另配Cortex-Debug，不把两种launch模板混抄。根据当前ST工具版本及实际路径配置，入口按钮可能随版本变化。

02-CubeMX的HAL工程由CubeMX生成，自己的代码放USER CODE区域，不把01-LED的启动文件/链接脚本再复制进去造成重复定义。

PC C++练习、WSL Linux程序、STM32固件分别使用自己的编译器和调试器。先在Windows完成现有STM32流程；未来要在WSL连接USB探头，需要额外配置，不属于“恢复Linux普通C++入口”自动完成的部分。
