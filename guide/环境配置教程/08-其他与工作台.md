# 其他教材、Python与学习工作台

## 不同教材的环境现状

| 主线 | 本区当前实现 | 不应误认为 |
|---|---|---|
| 计算机基础 | 宿主机C语言概念程序与阅读资料 | 真实硬件平台全部搭建 |
| 操作系统 | 宿主机概念模拟、逐日指引 | 所有章节都已成为可启动裸机OS |
| 编译器 | C语言配套例子与两本PDF | 已完成整本书的完整编译器 |
| 图神经网络 | C语言数学/聚合概念程序 | 已安装PyTorch/CUDA并完成GNN训练 |

这些配套概念程序用现有Windows C/C++构建工具即可；进入真正的裸机、完整编译器或深度学习项目时，再按项目补具体依赖。教材名字本身不能证明环境已安装。

## Python在这里做什么

学习工具使用Python管理构建、验收、图片示例和网页服务，不改变你正在学习C++的事实。当前任务里写的是Codex配套Python完整路径；终端里python可能指向另一个程序，可用Get-Command python.exe确认。

以后迁移到独立Python，需要同步VS Code task的command，并确认使用图像示例所需的依赖（例如Pillow）。Python环境与C++库环境不同，不把pip安装和C++链接混在一起。

## 工作台是不是要装前端框架

当前workbench是本地HTML/CSS/JavaScript加Python服务器，不要求npm、Node或Vite才能使用。Node/Playwright曾用于维护时检查页面，不是日常学习必备工具。

桌面“学习工作台”或运行workbench/start.py，服务后访问http://127.0.0.1:18765。直接双击HTML可能缺少/api/catalog数据；网页并不等于文件本身。

服务器提供章节资料与进度保存，学习状态写在guide/学习进度.csv。文档不能打开时看URL、服务器是否运行和路径；不要为“网页打不开”直接重装C++编译器。
