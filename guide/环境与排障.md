# 环境与排障

## 已配置

| 用途 | 工具与位置 |
|---|---|
| Windows C/C++ | D:\c++\MYSYS2\ucrt64\bin\gcc.exe、g++.exe、gdb.exe |
| Linux实验 | 已有WSL Ubuntu，已补齐build-essential、gdb、cmake、ninja、shellcheck、dos2unix、zip/unzip |
| OpenGL | MSYS2 UCRT64版本GLFW、GLEW、GLM；通过真实OpenGL4.3上下文和像素检查 |
| PPP辅助头 | 作者网站的std_lib_facilities.h，编译工具自动添加include路径 |
| FLTK | D:\Book-Learning\vendor\fltk\ucrt64，与现有系统文件隔离 |
| Graph_lib | 作者源文件保留于vendor/ppp2，兼容改动位于vendor/ppp2-adapted |

初次安装图形库时发现MSYS2镜像配置使用了错误的仓库路径。已备份mirrorlist.mingw并改为官方服务器的$repo路径，随后GLFW/GLEW/GLM安装成功。原镜像备份在tools/mirrorlist.mingw.before。
FLTK依赖与现有未登记文件冲突，所以FLTK采用独立目录，没有强制覆盖已有libpng/libjpeg文件。软件包来源及安装记录可由pacman查询，FLTK包保留在MSYS2包缓存中。

## 编译器与语言

C++默认C++17，图形学C默认C11。原书PPP主要讲C++11/14，标准语法练习可在当前工具链运行。语言导学涉及新旧提案时要区分出版年代语法与当前标准；遇到concept等C++20主题，可单独调整编译标准。
Windows普通程序不能访问STM32外设寄存器；硬件代码使用D:\STM32-Learning的ARM工具链。

## 常见问题

| 现象 | 处理 |
|---|---|
| 按编译但没生成想要的程序 | 先点中目标.c/.cpp，再选择该文件夹所属任务；不要对README执行编译 |
| 程序等待不动 | 很可能在等stdin，在任务终端输入题目要求的数据 |
| 找不到DLL | 用本工作区任务启动；它会给子进程添加UCRT64和FLTK运行库路径 |
| std_lib_facilities.h找不到 | 使用工作区的study.py编译任务，include路径已配置 |
| Graph_lib编译错误 | 使用Simple_window.h/Graph.h的程序会自动连接兼容副本；不要混用其他版本GUI文件 |
| Shell中出现^M、bad interpreter | 保存为LF，或在Ubuntu用dos2unix转换自己的脚本 |
| 权限实验和书上不同 | /mnt/d是Windows挂载盘；严格POSIX权限到Ubuntu home做，避免修改Windows个人文件权限 |
| OpenGL窗口黑屏 | 检查终端中的shader编译/链接错误、VAO、viewport及顶点位置；先复现first-triangle |
| GPU版本不支持 | 查看真实驱动版本；不要把上下文版本号改大就认为硬件支持 |

## Graph_lib兼容修改

原始下载保留不动，兼容副本修改如下：
- 为Point恢复双参数构造函数，以兼容书中Point(x,y)写法。
- 流状态检查显式转换为bool。
- 头文件中的随机函数标记inline，避免多文件链接重复定义。
- 图形对象默认颜色/字体设为黑色、Helvetica和14号，避免FLTK1.4在绘图驱动初始化前访问空指针。
- 构建时统一预包含教材辅助头；GUI.h实际来自作者的Gui.h（Windows不区分大小写）。

book_graph.cpp已通过几何对象自检；完整GUI交互可由你运行后观察。原库仍会产生部分年代相关编译警告，记录在tools/graph-lib-build.log。
