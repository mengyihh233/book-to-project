# 学习环境使用手册

平板用户先读[快速上手](平板联动快速上手.md)和[网页版VS Code手册](VSCode网页版使用手册.md)。当前网页版托管在Windows，终端可以进入WSL，源码共用。

## 日常分工与入口

| 内容 | 默认环境 | 打开入口 |
|---|---|---|
| Roberts C++、C语言图形学 | Windows + VS Code；Roberts也支持WSL C++ | 桌面“重点学习（Windows）”或工作台“在 VS Code 打开” |
| OpenCV机器视觉、OpenGL | Windows现有环境 | 对应学习工作区 |
| Linux命令行、Shell脚本 | WSL Ubuntu | 桌面“重点学习（WSL Ubuntu）”，显示C++与Linux学习目录 |

工作台：桌面“学习工作台”，或服务启动后访问http://127.0.0.1:18765。默认显示C++、OpenCV、高数；可切换全部主线。C++已恢复WSL开发入口；选择实际使用的环境检查当前题即可。

所有教材、源码、个人作答和状态都在仓库根目录。Windows与WSL读取同一份源码；个人作答与笔记保留。默认使用Ubuntu-22.04，旧发行版保留；编译器、GDB、CMake、Ninja、Python与ShellCheck保留。

## C++：从读题到检查

1. 打开workspaces/cpp.code-workspace，找到原书第1—5章中当前学习的题目目录。
2. 先读题目README，写出输入、输出与边界，手算一个例子。
3. 在work.cpp或work/main.cpp独立编码，Ctrl+S保存。
4. 菜单“终端→运行任务”，选当前文件编译、读取同目录input.txt、原书作答检查。Ctrl+Shift+B可选构建任务。
5. 失败时先看第一个编译错误，或比较期望与实际输出；字符串题中的前后空格有意义。
6. 完成后读solution，再写复盘。参考通过不会把你自动标记为完成。

reference.cpp是参考入口，lesson.h是部分题的参考函数；不要在自己的work中include答案来替代作答。input.h仅提供输入校验，可复用。tests.cpp检查参考接口，和检查自己的work是两件事。

命令行等价方式（PowerShell）：

```powershell
Set-Location '仓库根目录'
& 'C:/Users/lsy08/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe' tools/study.py run cpp/主教材/章节学习/第03章 字符串类string/课后习题/第17题 支持负数与大位移的凯撒替换/work.cpp --input cpp/主教材/章节学习/第03章 字符串类string/课后习题/第17题 支持负数与大位移的凯撒替换/input.txt
& 'C:/Users/lsy08/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe' tools/check-current.py cpp/主教材/章节学习/第03章 字符串类string/课后习题/第17题 支持负数与大位移的凯撒替换/work.cpp
```

下文简写python表示使用上面的Windows Python；VS Code任务已配置完整路径，无需手动设置别名。PowerShell文件输入使用--input，不照搬Bash的重定向语法。

## F5调试

打开具体.cpp文件，F9设断点，F5选择“Windows: 调试当前C++文件”。预启动任务把当前文件编译到固定的build/active-program.exe，避免不同工作区根目录使可执行文件路径指错。F10逐过程、F11进入函数、Shift+F5结束；查看变量面板与监视表达式。

普通运行按源码位置保存各自.exe；固定active-program.exe只用于当前调试。VS Code界面F5交互需要实际使用时观察，命令行构建和GDB断点会另做验证。

## 自己的检查与参考维护的区别

自己的题目统一运行“本题：检查作答”；SVG图形题也会自动选择专项。

“全部参考验收”仅用于维护配套资料，已从日常任务菜单隐藏。需要维护时，在学习根目录用相应Python运行tools/check-ch02.py或tools/check-ch03.py；它们不检查个人作答，也不记录完成。不是每次学习都要执行。

## Linux / WSL

WSL窗口左下角显示WSL: Ubuntu-22.04，仓库根目录对应仓库根目录。WSL工作区包含C++章节、原书题、笔记与Linux目录，已恢复C++编译、文件输入、当前作答检查及F5调试。具体步骤见[WSL开发说明](WSL学习环境.md)。

```bash
cd 仓库根目录
python3 tools/wsl-study.py shell linux/chapters/ch03/reference.sh
python3 tools/wsl-study.py lint linux/projects/dataset-audit/reference.sh
python3 tools/check-wsl.py
```

Shell脚本用LF；报含\r的语法错误时在VS Code右下角把CRLF改成LF并保存。当前两种入口都默认使用Ubuntu和ShellCheck，但实验输出所在的沙箱不同：

| 打开方式 | 任务/工具 | 沙箱目录 |
|---|---|---|
| Windows VS Code的“本题：运行作答” | Windows Python调用 `tools/study.py shell`，经WSL执行 | `仓库根目录/linux/sandbox/`，WSL对应 `仓库根目录/linux/sandbox/`，按章节/项目隔离 |
| WSL远程窗口的“本题：运行作答” | Linux Python调用 `tools/wsl-study.py shell` | `~/.cache/book-learning/sandbox/linux/`，按章节/项目隔离 |

`DATA` 都指向同一份 `linux/data` 样例。前者沙箱在D盘挂载目录，后者在Linux文件系统；学习Linux权限和符号链接时优先使用后者。不要把个人作答保存在沙箱或构建缓存中。ShellCheck检查静态问题；只有显式切换到Git Bash备用后端时，Windows“Shell：检查语法”才使用 `bash -n` 语法检查。

Windows工具的Shell后端仍为WSL，Git Bash只作备用。更完整的连接说明见[WSL学习环境](WSL学习环境.md)。

## 机器视觉

默认使用Windows已有OpenCV环境。先练Mat、灰度、ROI和阈值，再做[零件计数项目](../opencv/projects/parts-inspector/README.md)。

```powershell
python tools/inspect-parts.py --input 'D:/你的图片/零件01.png' --output '仓库根目录/opencv/output/我的检测01' --config opencv/projects/parts-inspector/config.json
```

用真实路径替换示例。输出目录必须未存在；批处理将--input换成--batch。查看overlay.png、mask.png和report.json。参数先复制到自己的notes中做对照，粘连、光照和尺度变化都需要实验，像素面积不是物理面积。

## 插件与排障

工作区推荐扩展不等于插件隔离；全局已安装也不等于全部激活。用“Developer: Show Running Extensions”查看实际运行者，按需要“禁用（工作区）”。严格隔离STM32、前端等用途需要VS Code配置文件，不能靠推荐列表实现。

| 现象 | 检查 |
|---|---|
| F5找不到程序 | 选择Windows调试任务，保存.cpp，观察预启动编译是否成功 |
| 程序等待不退出 | 输入是否齐全；优先用input.txt |
| 样例输出不同 | 提示语、空格、大小写、退出码与输入约定 |
| WSL连不上 | PowerShell运行wsl -l -v，再看VS Code“WSL: Show Log” |
| 工作台打不开 | 启动workbench/start.py，检查18765端口和workbench日志 |

学习状态在guide/学习进度.csv，个人笔记在各notes或work内。tools中的setup/create脚本属于内部记录，日常不要重跑覆盖作答。
